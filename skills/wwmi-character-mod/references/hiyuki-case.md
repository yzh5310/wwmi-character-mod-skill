# 绯雪「斩厄的雪刃」礼盒 Mod 案例（2026-10-16～17）

这是本技能里第一个「只有一张官方插画 → 图生 3D → 完整 WWMI Mod → 多轮材质修复 → 暂停」的全链路案例。它证明流程可行，也给出了质量上限与排错方法。案例中的路径、哈希、阈值只适用于当次采集，不能当通用模板。

## 需求与路线

用户提供了礼盒插画，要求把游戏内绯雪换成这套服装。没有三视图、没有可下载模型、没有现成 Mod；安装目录里的「国韵·落红」是另一套换装，不能靠改色得到。

路线：

1. imagegen 生成正面 A 姿态的服装参考（去掉脸、身体、头发、鞋、武器；补画部分明确标为推测设计）。
2. 本地 Hunyuan3D-2mini 图生 3D（固定 commit/revision/SHA256；`tools/hunyuan-shape-venv` 独立环境；`run_hiyuki_shape_pilot.py` 参数 30 步、octree 384、seed 固定）。输出 47 万点/94 万面，watertight，5 连通块，峰值显存 2.25GB。
3. 清理到 6 万面（3 连通块）、xatlas 自动 UV（接缝复制后 46,564 点、1592 图块）。
4. 采集游戏原装常驻 NPC 作为骨架/权重基线（用户没有可操作绯雪）。
5. 尺寸对齐、截面校准、拆袖封口、权重转移、WWMI 构建。
6. 贴图/材质迭代（v1–v20）与实机修复。

**关键判断：AI 网格只能当底稿。** 薄片、粘连、毛边、版型偏差是质量上限；后续切割/补洞/剪枝会进一步增加薄片和开放边界。若目标是「有质感」，优先复用官方网格重贴图，或限制对 AI 网格的切割。

## 原装基线采集要点

- 大世界常驻 NPC 与玩家角色共用部分渲染接口，可以作为制作基线，但不能替代动作/大招验证。
- 自动 SendInput 发送 F10/F8 没有产生采集文件；用户手动按键才成功。**不要用 SendInput 返回事件数当游戏真实响应。**
- 采集 7 部件、86,322 顶点、115,775 面、338 个非零权重骨骼编号、161 项形变（两批 52,582 + 17,340 条）。
- 首帧只抓目标绘制、缺计算通道；补采后按实际阶段约束 shapekey shader 哈希（本次 `cfa3cff1…`/`9bf4420c…`/`7a839618…`），未改上游源码。
- 临时停用的旧 Mod 要逐文件哈希核对后恢复；`hunting`/`analyse_options` 键级恢复。

## 网格管线教训

- 清理、UV、对齐、拆袖、封口各自可验证（闭合/绕序/相交/往返/边长/UV 保留），但**零相交不等于外形质量合格**。
- xatlas UV 会在接缝复制顶点：按顶点连通性统计的「1412 个碎片」不等于网格真的裂成 1412 片。判断几何是否破碎要看边界边、薄片和视觉，不要只看连通块数量。
- 直接摆动粘连的袖子会把边长拉 7.93 倍，必须撤回；给脚本加边长/退化门槛。
- 封口失败时按「固定边界重三角化 → 有界两圈重切 → 局部内衬」递进，避免用泛型补洞或移动原始边界。补面要保留源面 ID/UV 映射并做独立相交检测。
- 绑定优先整体网格 + 区域权重；为了权重方便把衣服切碎是后来「廉价感」的来源之一。

## WWMI 材质与贴图要点

- 权重：8 影响、UNORM8 和 255；合并骨骼编号 >255 用 BlendRemap；TEXCOORD/COLOR1 等辅助通道要从对应原装部件复制。
- 逐部件选择材质，绘制前保存、绘制后恢复槽位；远近/场景会切换贴图哈希，优先用 RabbitFX 语义接口。
- **贴图 alpha 是 RabbitFX 的启用开关，不是透明度**（本次契约：diffuse=102、cloth-normal=200、boot-normal=210、skin-normal=255、light=0）。写错会让靴子整条不渲染。
- 8×8 贴图对于常量 UV 部件是正确设计；不要把「贴图很小」直接当缺陷。
- DDS 编码要与原生一致：原生 diffuse 是 BC7_UNORM_SRGB，而 Pillow 写出的未压缩 DDS 是 UNORM → 写前把 diffuse 转线性，否则发灰。Pillow DDS 默认只有 1 级 mip，需要自建 mip 链（见 `scripts/dds_mips.py`）；法线逐级重新归一化。3dmigoto 能加载带 mip 的未压缩 DDS。
- 焊接法线、UV 切线、AO、织物细节都会改善观感，但改变不了网格本身的廉价感；调参要一次一个变量并做可比截图。

## 两个真实渲染 bug 的定位与修复（本案例最有复用价值）

### 1) 贴图 V 方向整体翻转

症状：衣料呈红黑碎块、看不出服装结构、像随机贴图。

根因：烘焙按图像空间写入（图像第 0 行 = V1），Direct3D 按「第 0 行 = V0」采样。每个 UV 岛取到镜像内容。

判定方法：用**采集的原生网格 + 原生贴图**做对照渲染，分别按两种 V 约定渲染，正确的一组会显示连贯的红裙/银边/靴子；再用出问题的 mod 数据按游戏约定模拟，能复现游戏画面。脚本见 `scripts/probe_texture_v_convention.py`。

修复：把 diffuse/normal 图集整体上下翻转再写 DDS。实机确认方法：临时把 diffuse 换成 UV 坐标渐变贴图（R=U、G=V），游戏里应显示大块连续渐变而不是碎块。

### 2) 组件4 前向通道未标记 → 法线图被当颜色（黄绿色块）

症状：某些视角出现黄绿色硬边色块。

判定方法：把可疑材质的平法线贴图临时改成品红/青/黄等诊断色，看画面色块是否跟着变色。会跟随 → 是贴图错绑，不是光照。

根因：组件4 的 G-buffer 顶点着色器 `6a6650a9db8983ce` 没被标记为前向通道，`vs == 62101` 只覆盖组件3的 VS。走 RabbitFX 分支后法线贴图被塞进 t0，而前向着色器在那里采样 diffuse。

修复：在生成的 mod.ini 增加

```ini
[ShaderOverride<Mod>ForwardVSComponent4]
hash = 6a6650a9db8983ce
filter_index = 62101
```

修复后用户实机确认色块消失。

## 运行时诊断技巧

- FrameAnalysis 里 `vb0` dump 文本的 `count=<合并顶点数>` 可识别 mod 网格的 draw（本次 84795）。
- RabbitFX ShaderRegex patch 后 PS 哈希会变（如 `f8c96a27…` → `36b2debf…`），不能用采集时的旧哈希搜。
- 前向标记 `vs == 62101` 来自其他 Mod 的 ShaderOverride，**全局生效**；要检查它是否覆盖当前对象所有 G-buffer VS 变体。
- 自动按键不可靠：刷新/采集失败先让用户手动按 F10/F8，并验证焦点与实际新增文件。
- `hunting=0` 禁用、`1` 直接启用、`2` 软禁用需切换；按当前版本的 `d3dx.ini` 注释核对。
